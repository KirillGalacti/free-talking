# Свободные переговоры — «Арена переговоров»

Режим свободных переговоров с настраиваемым ИИ-контрагентом: выбор сессии → настройки → сборка скрытой карточки контрагента → бриф → видео-встреча (голос или текст) → разбор по 12 навыкам → перезапуск с критического момента.

Отдельный проект; стек и Yandex Cloud — те же, что в общем проекте `ai-negotiation-arena`.

## Стек

- React 19 + Vite + TypeScript, Tailwind CSS 4, компоненты в стиле shadcn/ui;
- Node.js + Express 5 + TypeScript (tsx);
- YandexGPT через OpenAI-совместимый API (`yandexgpt/latest`, резерв — `yandexgpt-5-lite`);
- Yandex SpeechKit: распознавание (STT) и озвучивание реплик контрагента (TTS);
- MediaRecorder API → PCM 16 кГц (как в общем проекте).

## Запуск

Нужен Node.js 20+ и файл `.env` в корне (ключи общего проекта уже перенесены):

```env
YANDEX_API_KEY=...
YANDEX_FOLDER_ID=...
API_PORT=3002
```

```powershell
npm.cmd install
npm.cmd run dev
```

Откройте http://127.0.0.1:5174 (порты отличаются от общего проекта — 5173/3001, — поэтому оба можно запускать одновременно).

Прочее: `npm.cmd run build` — сборка, `npm.cmd start` — сервер со сборкой на `API_PORT`, `npm.cmd run test:unit` — тесты.

## Экраны и макеты

Все экраны сверстаны на эталонном холсте 1920×1080 и масштабируются целиком под окно (пропорции макета сохраняются при любом разрешении). «Полный разбор» — холст 1920×3170 с прокруткой.

| Макет | Маршрут / состояние |
| --- | --- |
| 1 · ситуация и цель (все 5 вариантов) | `/` — способ, тематика, роль, цель; подсветка текущего шага |
| 2 · контрагент и сложность | `?screen=counterparty` |
| 3 · настроить подробнее | `?screen=details` |
| 2 · точная настройка · своя ситуация | `?screen=exact` (поиск реальных названий + «Заменить на «Клиент»») |
| 2 · согласованный рандом · закрепите | `?screen=random` |
| 2 · согласованный рандом · ситуация собрана | `?screen=random-result` |
| 2 · повтор по seed · выбор сессии | `?screen=seed` |
| сборка контрагента / сбой генератора | модалки поверх экранов настройки |
| 4 · проверка перед стартом | `?screen=brief` |
| встреча · ваш ход / текст / ввод текстом / запись / расшифровка / ответ контрагента / завершение / развёрнутый бриф / пауза / подтверждение завершения / ошибка связи | `?screen=meeting&seed=…` — состояния одного экрана |
| разбор встречи / разбор · без сделки | `?screen=report&session=…` (вариант выбирается по исходу) |
| полный разбор | `?screen=full-report&session=…` |
| перезапуск с критического момента | `?screen=replay&session=…&moment=M1` |
| встреча · перезапуск · ваш ход | `?screen=meeting&replay=…&moment=…` |

В режиме разработки состояния можно открыть без ИИ: `?fixture=preset|random|seed|exact`, `&fixtureBrief=preset|random`, `?screen=meeting&fixture=preset&fixtureBrief=preset&demo=text|typed|recording|review|speaking|finished|pause|finish|connection|brief`, `?screen=report&fixtureSession=deal|nodeal`. В сборке эти параметры отключены.

## Логика переговоров

Как в реализованной части общего проекта, дополнено по спецификации «Модель ИИ-контрагента» и «Завершение AI-сессии»:

- **Сборка контрагента** (`POST /api/scenario/assemble`). YandexGPT создаёт скрытую карточку (цель, интересы с условиями раскрытия, BATNA, красные линии, полномочия, целевой пакет, диапазоны, уступки только в обмен, скрытые факты, возражения) и согласованный с ней публичный бриф. Сервер детерминированно проверяет связность (красная линия не в целевом пакете, BATNA не копия позиции, интересы не утекли в бриф, у возражений есть условие закрытия, стиль не противоречит тактикам) и при ошибке один раз просит исправить. Карточка замораживается по seed в `data/scenarios.json` и **никогда не отдаётся в браузер**.
- **Согласованный рандом**: seed детерминированно выбирает все незакреплённые параметры; закреплённые не меняются.
- **Повтор по seed** загружает ту же замороженную карточку. Готовый сценарий `01JFREE9X3` («Жёсткий закупщик») встроен и используется при сбое генератора.
- **Встреча** (`POST /api/chat`): системная инструкция контрагента из скрытой карточки и профиля, структурированный ответ модели; идемпотентные ходы по `clientEventId`; голос → SpeechKit → правка текста → отправка; озвучивание реплик; пауза останавливает таймер и реплику; при обрыве связи реплика сохраняется и отправляется повторно тем же ходом.
- **Завершение решает сервер, а не модель**: сделка/отказ/выход контрагента принимаются только после двух ходов участника; при лимите ходов или истёкшем таймере — запрос итога («Подведите итог»), одна заключительная реплика и блокировка ввода; ручное завершение — с подтверждением.
- **Разбор** (`POST /api/analyze`): 12 навыков по шкале 0–4, N/A вместо нуля при отсутствии возможности; критические моменты, сильное решение, точка роста, предложения, уступки (условные/безусловные), хронология, что узнали, проверка границ. Сервер отбрасывает ссылки на несуществующие реплики.
- Сессии сохраняются в `localStorage` (как попытки в общем проекте); перезапуск продолжает встречу с выбранного момента с той же скрытой позицией и таймером.

## API

`POST /api/scenario/assemble`, `POST /api/scenario/preset`, `GET /api/scenario/:seed`, `POST /api/chat`, `POST /api/transcribe` (multipart, поле `audio`, PCM 16 кГц), `POST /api/tts`, `POST /api/analyze`.

## Безопасность

`.env` и `data/*.json` исключены из Git; ключи Yandex Cloud используются только на сервере; размеры входных данных ограничены; реплики транскрипта передаются оценщику как данные, а не инструкции.
